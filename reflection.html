Reflection

On makerspaces and owning what you build

Building this site with plain HTML, CSS and JavaScript instead of a website builder or a framework has changed how I think about what it means to make something for the web. A drag-and-drop builder gives you a page, but the page belongs to the platform — it lives inside someone else's system, formatted the way their templates allow, exportable only on their terms. Writing the markup and the styles myself means the opposite is true: every file on this site is mine, in a folder I control, that I can move, rewrite, or host anywhere I choose.

"Learning the raw materials of the web is what turns you from a tenant of a platform into someone who actually owns their corner of it."

That distinction is really what a digital makerspace is about. A physical makerspace gives people access to tools — a laser cutter, a 3D printer, a soldering iron — that they'd otherwise never get hands-on time with, so they can build things instead of only buying finished products. A course like this one functions the same way for the web: it hands you the browser's raw tools directly, rather than a polished no-code interface that hides how the page actually works. The skill you walk away with isn't "how to use this one tool," it's "how the web itself is built," which stays useful no matter which tool disappears next.

The other side of that is data sovereignty — who actually controls the content and code once it exists. When I build with a hosted site builder, my portfolio's HTML is generated on the fly by a company's servers, and if that company changes its pricing, shuts down a feature, or discontinues the product, my site can break or disappear with it. This repository of plain files doesn't have that dependency. I can host it on GitHub Pages today and move it to any other web host tomorrow, because nothing about it depends on a proprietary system staying alive. Understanding HTML, CSS and JavaScript directly is, in a small but real way, a form of keeping ownership of my own work.

What do you think about data sovereignty? Share your thoughts.
